### Виконання роботи

#### Що було розглянуто:

1. **Порівняння функціонального та об'єктно-орієнтованого підходів**

   На прикладі карткової гри спочатку реалізовано функціональний підхід (через словники та функції), а потім той самий код переписано з використанням класів.

   **Функціональний підхід** — карта як словник:
   ```python
   def draw_card():
       return {
           "name": random.choice(names),
           "attack_power": random.randint(4, 8),
           "durability": random.randint(30, 60),
           "magic_attribute": f"Магія: {random.choice(magic_types)}"
       }
   ```

   **ООП підхід** — карта як клас:
   ```python
   class Card:
       def __init__(self, name, attack_power, durability, magic_attribute):
           self.name = name
           self.attack_power = attack_power
           self.durability = durability
           self.magic_attribute = magic_attribute
       
       def __str__(self):
           return f"{self.name} | Атака: {self.attack_power} | Захист: {self.durability}"
   ```

2. **Базові концепції ООП**

   | Концепція | Опис |
   |-----------|------|
   | **Клас** | Шаблон (blueprint) для створення об'єктів |
   | **Об'єкт** | Екземпляр класу з конкретними даними |
   | **Атрибути** | Дані, що зберігаються у об'єкті |
   | **Методи** | Функції, що описують поведінку об'єкту |
   | **`__init__`** | Конструктор — метод ініціалізації об'єкту |
   | **`__str__`** | Магічний метод текстового представлення |
   | **`self`** | Посилання на поточний екземпляр класу |

3. **Практична симуляція карткової гри**
   - Два гравці витягують по 3 карти
   - Карти взаємодіють між собою: атака зменшує витривалість
   - Коли витривалість падає до 0, карта "вибуває" з гри
   - Гравець витягує нову карту, якщо вона ще залишилась

4. **Переваги ООП перед функціональним підходом**
   - Код стає більш організованим та читабельним
   - Об'єкти є детермінованими (завжди мають однакову структуру)
   - Легше додавати нову функціональність
   - Простіша взаємодія між об'єктами
